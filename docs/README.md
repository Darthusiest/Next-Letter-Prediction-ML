# Project Documentation Index

This `docs/` folder is for **research-style documentation** that can later be
used as material for a paper about this project.

Suggested structure (feel free to extend or rename):

- `design.md` — overall problem definition, modeling choices, architecture.
- `data.md` — datasets used, preprocessing steps, PDF/EPUB→TXT conversion.
- `experiments.md` — training runs (hyperparameters, metrics, observations).
- `analysis_notes.md` — error analyses, interesting examples, failure modes.
- `todo_research.md` — open questions and ideas to test.

Each document should capture:

- **What** was added or changed (code, data, configuration).
- **Why** it was done (goal, hypothesis, constraint).
- **How** it was done (brief method, key files/functions).
- **Results / impact** (metrics, qualitative observations).

You can start by creating these files and adding short notes after each
meaningful change to the codebase or training procedure.
